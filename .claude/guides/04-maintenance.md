# 維護協議：怎麼安全地更新這套制度

> 這套檔案（CLAUDE.md ＋ .claude/guides/ ＋ .claude/memory/）是本環境的制度。
> 制度要活就要能更新；要可信就不能被隨手改壞。本檔規定誰能改什麼、怎麼改。

## §1 改之前：備份

修改 CLAUDE.md 或 .claude/guides/ 任何檔案前，先複製一份：

```
cp <原檔> .claude/backups/YYYYMMDD-<原檔名>
```

例：`cp CLAUDE.md .claude/backups/20260705-CLAUDE.md`（日期用當天日期）。同一天改同一檔第二次，不用再備份。
`.claude/memory/LESSONS.md` 的**追加**不用備份；**刪減或改寫**既有條目才要。

## §2 權限分級

**可以自行改（不用問使用者）**：
- 追加教訓到 `.claude/memory/LESSONS.md`（格式見 §3）。
- 修正事實性錯誤：工具改名、路徑失效、模型清單變動——前提是你用工具實測確認過新事實（例如 Agent schema 的 model enum 變了），並在改動處加上「YYYY-MM-DD 實測更新」。
- 為既有判準補充正例/反例（不改判準本身）。
- 更新 `00-diagnosis.md` 裡已被修復的問題狀態（例如 index.html 重構完成後，把 D2 標記為已解決並註明日期）。

**要先問使用者才能改**：
- 刪除或放寬任何「硬規則」（CLAUDE.md 硬規則區、各 guide 裡標明「規則，立即生效」的條目）。
- 改動門檻數字（派工門檻、重試上限、升級條件）。
- 改變 CLAUDE.md 的路由結構或新增/刪除 guide 檔。
- 任何你「覺得這條規則不合理」的情況——不合理可能是規則錯，也可能是你缺上下文。把質疑寫進 LESSONS.md 的「待議」段並問使用者，不要直接改。

**永遠不准改**：
- `~/.claude/` 下的 hooks 與 launcher 設定（平台管理）。
- 把失敗改寫成成功的任何紀錄。

## §3 教訓怎麼寫（.claude/memory/LESSONS.md）

每條教訓固定四行，追加到檔尾：

```
## YYYY-MM-DD 一句話標題
情境：什麼任務、什麼操作。
教訓：發生什麼、正確做法是什麼（要具體到可直接照做）。
證據：錯誤訊息關鍵句 / commit hash / 檔案:行號。
```

收錄標準：
- **收**：踩過的坑（含正確解法）、實測確認的環境事實（例如「某網站 WebFetch 會 403，改用 X 可行」）、被使用者糾正的偏好。
- **不收**：repo 或 guides 已寫明的事、一次性的瑣事、猜測（沒實測過的不是教訓）。
- 已有相近條目就更新該條（改日期），不要開新條。發現某條教訓是錯的，整條刪除。

## §4 精簡時機

- `LESSONS.md` 超過 **40 條或 300 行**：做一次整併——合併同類、刪除已寫進 guides 的、把通用性高的教訓升格進對應 guide（升格屬於「補充正例/反例」時可自行做，屬於改規則時要問）。整併前備份。
- 任何單一 guide 超過 **150 行**：檢查是否有可刪的重複與過時內容；結構性拆分要問使用者。
- `.claude/backups/` 超過 20 個檔案：刪掉三個月以前的備份。

## §5 每次 session 收尾的維護動作（30 秒）

1. 這次有踩坑或學到環境事實嗎？有 → 按 §3 追加一條。
2. 這次有發現 guides 內容與現實不符嗎？有 → 按 §2 權限分級處理。
3. 追加的內容 commit + push（制度檔沒 push 等於沒寫）。
